# 설계와 제품 범위

이 플러그인은 사용자가 요청할 때 LMS 정보와 로컬 자료를 가져와 에이전트의 작업에 연결한다. Syllo의 별도 서버·UI·계정·DB에 의존하지 않는다.

## Syllo에서 가져온 검증된 접근

- 고려대 Canvas API origin과 LearningX/LTI 인증 경로 구분
- 파일 목록이 제한된 과목에서 모듈과 주차학습으로 자료 찾기
- 과목 약칭을 실제 수강목록에 연결하고 주차·장·자료 번호를 구분
- PDF 원문과 실제 페이지에 근거한 학습
- 과제 제출·영상 완료·출결 판정을 각각 구분하고 unknown을 보존
- 자격 증명이 다른 호스트로 넘어가지 않게 차단

Syllo의 과거 검증을 새 플러그인의 실행 증거로 간주하지 않는다. 새 런타임과 설치 형태를 별도로 테스트한다.

## Syllo에 남기는 가치

웹/모바일 대시보드, 통합 캘린더 화면, 상시 동기화·메일 알림, 장기 학습 기록·노트 관리, 다중 사용자 서비스, 협업·계정 운영은 복제하지 않는다. 이 플러그인은 이미 Codex/Claude Code를 사용하는 학생의 요청형 작업 도구다. PDF를 공부하고 다른 도구에 연결하는 유연함을 제공하며 일상적인 학사 관리 앱 전체를 대체하려 하지 않는다.

## 구성

0.2.0부터 기본 MCP 런타임을 `plugin/dist/server.mjs`에 번들한다. 설치 후 clone이나 node_modules 경로에 의존하지 않는다. 자격 증명이 없으면 로컬 브라우저 설정을 반환하고, 연결 완료 후 같은 MCP 세션에서 설정을 다시 읽는다. PDF 엔진만 최초 분석 때 고정 lockfile로 자동 준비한다.

사용자가 여는 PDF는 바탕화면의 Canvas LMS/학기/과목/실제파일명에 보관한다. 계정별 내부 해시 캐시는 별도로 두며 접근권·버전 확인 후 재사용한다. 파일명 충돌과 사용자의 수정본은 보존한다. 캐시 삭제 후에도 변경되지 않은 보관본이 있으면 네트워크 다운로드 없이 복원한다.

```text
Codex / Claude Code
  ├─ plugin/skills/canvas-lms: 한국어 작업 절차
  └─ 로컬 MCP (stdio)
       ├─ Canvas API + LearningX: 필요한 과목의 정보 조회
       ├─ 계정별 파일 캐시: PDF, 추출 텍스트, 페이지 이미지
       └─ 결과를 호스트 모델에 전달

메일 전달 요청 → 호스트가 별도로 연결된 Gmail/메일 도구 사용
```

AI 요약/퀴즈 API를 중복 구축하지 않는다. 호스트 모델이 `index_pdf`로 얻은 전체 로컬 자료와 `read_pdf`/`render_pdf_page`를 사용해 설명한다. 자료를 모두 받는 것과 모든 페이지를 이미 분석했다고 주장하는 것은 구분한다.

학교 도구는 성공/부분 실패를 구분한다. 메모리 목록 캐시는 1~2분, LTI 세션은 최대 4분이다. 캐시 재사용 시에도 자료 접근권은 새로 확인한다. 내용 해시는 동일 계정 내 원본 중복을 없애며, 프로세스 간 잠금과 원자적 저장으로 앱 간 공유를 지원한다.

현재 한계: 고려대만 지원, 개인 토큰 방식, PDF 다운로드·분석과 MP4·비암호화 HLS 저장, 스캔 전체 OCR 미포함, 실시간 푸시/백그라운드 알림 없음. 일반 파일 첨부·타 대학·OAuth는 별도 요구와 검증이 필요하다.

Codex와 Claude의 MCP manifest를 분리하여 각 호스트의 공식 경로 placeholder를 사용한다. 현재 Codex의 미치환 동작은 CODEX_HOME 아래 해당 버전 설치 패키지를 찾는 fallback으로 지원한다. 개발 clone은 참조하지 않으며 패키지 검사에서 fallback 버전을 검증한다.


## 0.3.0 조회와 저장 흐름

일반 조회는 과목명과 의도로 바로 처리한다. 과제 상태는 서버에서 전체 목록에 필터를 적용한 뒤 페이지를 나누며, 미확인·면제·온라인 제출 대상 아님은 미제출과 구분한다. 첨부 자료는 과제 본문의 학교 파일 링크에서 식별하고, 숨김 파일은 원문 과제를 다시 확인한 뒤에만 다운로드한다.

`save_pdf_to_folder`는 호스트가 확인한 목적지 절대 경로에 PDF 사본을 내보낸다. 기존 파일은 덮어쓰지 않고 내용이 같으면 재사용한다. 자연어의 폴더명 해석은 호스트 파일 도구가 담당하며 클라우드와 사용자 PC 파일시스템을 혼동하지 않는다.

`open_dashboard`는 선택형 로컬 보조 화면이다. 채팅 안의 위젯이나 호스팅 서비스가 아니다. 학교 API 요청은 서버 측 기존 Canvas/LearningX 경로를 재사용하며 브라우저에 자격 증명을 전달하지 않는다. 학교 콘텐츠는 textContent로 렌더링하고 현재 계정 접근을 데이터 요청마다 확인한다.

연결 폼은 same-origin Referrer-Policy와 세션별 CSRF 검증값을 사용한다. 개인정보 보호 브라우저의 null/누락 Origin도 올바른 검증값이 있어야 수락하고, 명시적 외부 Origin은 검증값 유무와 무관하게 차단한다.


## 0.4.0 영상 다운로드

`download_video`는 find_materials의 영상 resourceId를 받아 MP4 또는 오프라인 HLS를 저장한다. Canvas MP4 파일과 LearningX의 직접 미디어 URL/Commons content.php 메타데이터를 지원하며 story_list의 여러 파일을 순서대로 보존한다. 학교의 실제 응답과 CDN 호환성은 실계정 검증이 별도로 필요하다.

진행 중인 영상은 계정별 video-downloads 아래에 두고 완료 파일은 지정 폴더 또는 기본 보관 폴더의 학기/과목/주차에 보존한다. MP4는 컨테이너·길이·해시를 확인하며 ETag/Last-Modified를 이용한 안전한 Range 이어받기를 지원한다. 완료 사본을 참조하므로 성공한 영상의 전체 바이트를 캐시에 중복 보관하지 않는다. 중단된 임시 파일은 재시도를 위해 남으며 성공 시 정리한다.

HLS는 완료된 VOD만 선택하고 높은 대역폭의 화질 및 기본 음성 트랙을 함께 저장한다. MPEG-TS와 fMP4 초기화/구간, 바이트 구간을 지원하며 암호화·실시간 목록·외부 호스트는 거절한다. URL 없는 로컬 m3u8과 구간 파일로 내보내므로 별도 변환 도구가 필요하지 않다. HLS를 MP4로 병합하거나 여러 Commons 파일을 합치는 기능은 제공하지 않는다.

공개 LearningX 다운로드 프로젝트의 Commons 필드 구조는 형식 조사에만 참고했다. 런타임과 회귀 검사는 이 저장소에서 독립 구현한 합성 자료로 검증하며 참고 프로젝트의 성공을 고려대 실계정 검증으로 표현하지 않는다.


## 0.5.0 공지·게시판 원본과 공급 경로별 상태

공지/게시글 HTML은 텍스트와 별도로 허용된 Commons iframe을 추출한다. 식별자는 board:<과목>:<게시판>:<글>:<콘텐츠> 또는 announcement:<과목>:<공지>:<콘텐츠>이며 file/lx ID를 재사용하지 않는다. 다운로드 시 계정·수강 과목과 최신 원문을 다시 확인한다. 기존 PDF 첨부와 공지 본문도 유지하며 숨김 첨부는 현재 원문 참조를 검증한다.

find_materials는 게시판 영상도 검색한다. 기본 검색은 우선순위 게시판부터 최대 10개/40개 글로 제한하고 boardSearch에 검사한 범위·남은 게시판·추가 페이지 가능성을 반환한다. 전체 열람이 끝나지 않았으면 sources.boards는 partial이다. files/modules/learningx/boards 경로별 상태를 보존해 일부 파일 경로의 401을 전체 토큰 만료로 취급하지 않는다.

영상 원본 후보는 검증 후 progressive/all → mobile → pseudo 등 우선순위로 유지하며 실패 시 다음 후보를 시도한다. 학교 CDN origin을 공통 상수로 관리하고 검증된 원본 Referer를 MP4·HLS·이어받기·리다이렉트에 전달한다. Authorization과 Cookie는 전달하지 않는다. 응답/알림/디스크 상태에는 후보 원본 URL·서명 값을 남기지 않는다.

download_videos는 순차 배치로 개별 성공·실패·미실행 수와 파일 크기·재시도 상태를 보고한다. 원문 제목/본문의 강의 날짜는 게시 시각과 분리하며, 모호한 날짜는 자동 이름을 만들지 않는다. 여러 원본은 날짜-01, -02로 저장하고 동명 파일은 해시 비교 후 보존한다. 부분 완료는 전체 성공으로 보고하지 않는다.

대시보드에서도 공지의 영상과 주차학습의 수강 완료/미완료/확인 불가를 표시한다. 실제 출결 상태는 별도 표시하며 새로고침은 현재 보고 있는 데이터 공급 경로의 캐시도 갱신한다.
