# 설계와 제품 범위

이 플러그인은 사용자가 요청할 때 LMS 정보와 로컬 자료를 가져와 에이전트의 작업에 연결한다. Syllo의 별도 서버·UI·계정·DB에 의존하지 않는다.

## Syllo에서 가져온 검증된 접근

- 고려대 Canvas API origin과 LearningX/LTI 인증 경로 구분
- 파일 목록이 제한된 과목에서 모듈과 주차학습으로 자료 찾기
- 과목 약칭을 실제 수강목록에 연결하고 주차·장·자료 번호를 구분
- PDF 원문과 실제 페이지에 근거한 학습
- 과제 제출·영상 완료·출결 판정을 각각 구분하고 unknown을 보존
- 자격 증명이 다른 호스트로 넘어가지 않게 차단

Syllo의 과거 검증을 새 플러그인의 실행 증거로 간주하지 않는다. 새 런타임과 설치 형태를 별도로 테스트한다.

## Syllo에 남기는 가치

웹/모바일 대시보드, 통합 캘린더 화면, 상시 동기화·메일 알림, 장기 학습 기록·노트 관리, 다중 사용자 서비스, 협업·계정 운영은 복제하지 않는다. 이 플러그인은 이미 Codex/Claude Code를 사용하는 학생의 요청형 작업 도구다. PDF를 공부하고 다른 도구에 연결하는 유연함을 제공하며 일상적인 학사 관리 앱 전체를 대체하려 하지 않는다.

## 구성

0.2.0부터 기본 MCP 런타임을 `plugin/dist/server.mjs`에 번들한다. 설치 후 clone이나 node_modules 경로에 의존하지 않는다. 자격 증명이 없으면 로컬 브라우저 설정을 반환하고, 연결 완료 후 같은 MCP 세션에서 설정을 다시 읽는다. PDF 엔진만 최초 분석 때 고정 lockfile로 자동 준비한다.

사용자가 여는 PDF는 바탕화면의 Canvas LMS/학기/과목/실제파일명에 보관한다. 계정별 내부 해시 캐시는 별도로 두며 접근권·버전 확인 후 재사용한다. 파일명 충돌과 사용자의 수정본은 보존한다. 캐시 삭제 후에도 변경되지 않은 보관본이 있으면 네트워크 다운로드 없이 복원한다.

```text
Codex / Claude Code
  ├─ plugin/skills/canvas-lms: 한국어 작업 절차
  └─ 로컬 MCP (stdio)
       ├─ Canvas API + LearningX: 필요한 과목의 정보 조회
       ├─ 계정별 파일 캐시: PDF, 추출 텍스트, 페이지 이미지
       └─ 결과를 호스트 모델에 전달

메일 전달 요청 → 호스트가 별도로 연결된 Gmail/메일 도구 사용
```

AI 요약/퀴즈 API를 중복 구축하지 않는다. 호스트 모델이 `index_pdf`로 얻은 전체 로컬 자료와 `read_pdf`/`render_pdf_page`를 사용해 설명한다. 자료를 모두 받는 것과 모든 페이지를 이미 분석했다고 주장하는 것은 구분한다.

학교 도구는 성공/부분 실패를 구분한다. 메모리 목록 캐시는 1~2분, LTI 세션은 최대 4분이다. 캐시 재사용 시에도 자료 접근권은 새로 확인한다. 내용 해시는 동일 계정 내 원본 중복을 없애며, 프로세스 간 잠금과 원자적 저장으로 앱 간 공유를 지원한다.

현재 한계: 고려대만 지원, 개인 토큰 방식, PDF만 다운로드·분석, 스캔 전체 OCR 미포함, 실시간 푸시/백그라운드 알림 없음. 일반 파일 첨부·타 대학·OAuth는 별도 요구와 검증이 필요하다.

Codex와 Claude의 MCP manifest를 분리하여 각 호스트의 공식 경로 placeholder를 사용한다. 현재 Codex의 미치환 동작은 CODEX_HOME 아래 해당 버전 설치 패키지를 찾는 fallback으로 지원한다. 개발 clone은 참조하지 않으며 패키지 검사에서 fallback 버전을 검증한다.
